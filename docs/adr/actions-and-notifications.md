# 操作はアクションとして用意してキーは利用者が決め、通知は見ていないものだけを OS の通知で出す

## 状況

herdr では、ペインに移ればすぐに入力でき、herdr 自体の操作は prefix キーで行っていた。通知はトーストと音を使っていた。

Claude Code や Codex は `Esc` を使う。done は「見ていない間に終わった」という印で、Herdr アプリとも共有する（`herdr.seen`）。

## 決定

- 新しいターミナルを開く（新しいタブページ、縦分割、横分割）、ウィンドウの移動、サイドバーの開閉などを、アクションとして用意する。グローバルなキーは利用者が設定で割り当てる。
- 新しいターミナルは、フォーカスしているターミナルのフォルダーで、シェルを起動する。ターミナルでないウィンドウにいるときは、Neovim の cwd を使う。
- サイドバーで選んだターミナルは、表示しているウィンドウがあればそこへ移り、なければ新しいタブページに開く。開き方は、あとから足せるように差し替えやすく作る。
- ターミナルのウィンドウに移ったら、自動でターミナルモードにする（設定で切れる）。抜けるキーは利用者が決め、プラグインは `Esc` を割り当てない。
- `blocked` と `done` になったら通知する。Neovim が前面にあり、そのターミナルが画面に表示されているときは通知しない。
- 通知の既定は OS の通知にし、方法は利用者が差し替えられる。
- done は、Neovim が前面にあり、そのターミナルが画面に表示されたら消す。サイドバーから未読に戻せる。

## 結果

得たもの:

- herdr と同じく、ターミナルに移ればすぐに入力できる。
- キーの割り当てが、利用者のほかの設定とぶつからない。
- Neovim が裏にあっても、待っているエージェントに気づける。誰も見ていない画面のせいで、スマートフォン側の done が消えることもない。

失ったもの:

- 初期のキーの割り当てがないので、使い始める前に設定が要る。
- Windows で Neovim から OS の通知を出す方法は、まだ決めていない。

## 採らなかった案

- 開くときに、いまのウィンドウや分割をキーで選べるようにする。まずは「表示中ならそこへ、なければ新しいタブページ」だけにし、差し替えられる作りにしておく。
- Neovim の標準のまま、ターミナルに移ってもノーマルモードにする。入力のたびに `i` が要る。
- 通知を Neovim の中だけにする。Neovim が裏にあると気づけない。
- done を、サイドバーで選んで開いたときだけ消す。表示しながら作業しているエージェントに、終わるたびに done が付く。
