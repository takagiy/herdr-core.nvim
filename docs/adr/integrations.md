# エージェントごとの差は Lua の integration の定義にまとめ、フックは nvim -l の共通スクリプトで動かす

## 状況

会話の再開には、各エージェントの設定にフックを入れる必要がある（[再起動後の復元](restore-after-reboot.md)）。入れ方はエージェントごとに違う。

- 設定ファイル（JSON、TOML）にフックのコマンドを書くもの（claude、codex など）と、拡張のファイル（JavaScript／TypeScript）を置くもの（pi、opencode など）がある。
- フックが受け取る会話 ID の項目名が違う。環境変数で受け取るものや、標準出力に JSON を返す必要があるものもある。
- codex のフックは、親の codex の会話 ID を `CODEX_THREAD_ID` で受け継ぐ。codex の中から起動した codex では、親の ID が入る（`codex exec` で確かめた）。

Herdr TUI はこれらを Rust と、エージェントごとの sh／PowerShell のスクリプトで扱っている。

## 決定

- integration は、名前をキーにした Lua の表で定義する。組み込みの定義も同じ形で書き、`setup` で渡した表を項目ごとに重ねる。
- フックの処理は、`nvim -l` で動く Lua のスクリプト 1 本にする。エージェントごとの差は、そのスクリプトの引数で吸収する。
- 設定ファイルは文字列のまま書き換え、自分の値以外（コメント、キーの順番、改行）はそのまま残す。

## 結果

得たもの:

- エージェントを足すのも、再開コマンドを変えるのも、`setup` の表に書くだけで済む。
- フックの処理は 1 本で、Windows と Mac で同じものが動き、プラグインのテストと一緒にテストできる。

失ったもの:

- フックの実行に `nvim` の起動（数十ミリ秒）がかかる。
- `NVIM_APPNAME` を変えるとスクリプトの場所が変わり、古いフックが自分のものと見なされずに残る。
- TOML を完全には解析しないので、変わった書き方の設定ファイルでは失敗することがある。
- label の名前と値の形が、自作のフックのための公開の API になり、変えにくくなる。

## 採らなかった案

- エージェントごとに sh と PowerShell のスクリプトを用意する（Herdr TUI と同じ）。同じ処理を 2 つの言語で持つことになる。
- JSON を表に読み込んでから書き直す。コメントが消え、キーの順番が変わる。
- 使う integration をリストで並べる。1 つ書くと、書かなかった組み込みが全部使われなくなる。
- 拡張から `hc label` を直接実行する。label の扱いが Lua のスクリプトと拡張に散らばる。
