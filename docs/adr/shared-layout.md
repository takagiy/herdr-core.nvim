# 配置は hc の doc に保存し、複数の Neovim で同期して、起動時は常に復元する

## 状況

Neovim を閉じても、ターミナルは hc の core で動き続ける。開き直したときに、前と同じ並びで続きを使いたい。Neovim を複数開くこともある。

hc の core は、名前付きの JSON を保存できる（doc。`doc.get` / `doc.set`）。版の番号で、同時の書き込みがぶつかるのを防げる。`hc events --doc` で変更を受け取れる。

## 決定

- タブページの並び、分割の形、どのウィンドウにどのターミナルを表示しているかを、プラグイン用の doc `herdr-core-nvim` に保存する。
- 同じ core につないでいる Neovim は、すべて同じ配置を共有し、変更を互いに反映する。
- フォーカス、ウィンドウの大きさ、サイドバーの開閉は、Neovim ごとに持つ。
- ファイルのウィンドウは同期しない。ターミナルとファイルが混ざったタブページは、ファイルのウィンドウを除いて同期する。配置が変わったときにファイルのウィンドウをどこに残すかは、実装しやすい方法にする。
- Neovim を起動したら、起動のしかたに関係なく配置を復元する。
- ウィンドウを閉じても、ターミナルのプログラムは終了させない。
- プログラムが終わったターミナルのウィンドウは閉じる。

## 結果

得たもの:

- どの Neovim を開いても、同じ並びでエージェントが続きから使える。
- 配置の保存に、Neovim のセッションのプラグイン（persisted.nvim など）が要らない。
- `:q` でうっかりエージェントを止めることがない。

失ったもの:

- `git commit` などで Neovim を開いたときも、配置が復元される。
- 使わなくなったシェルは、`exit` するまで残り続ける。
- 同じタブページでも、Neovim ごとにファイルのウィンドウの有無が違う。

## 採らなかった案

- 配置は 1 つだけ保存し、2 つ目の Neovim は空で開く。同期したい。
- 開いたフォルダーごと、または名前ごとに配置を保存する。普段は `~` で 1 つの Neovim を使う。
- persisted.nvim に保存を任せる。プラグインだけで完結させたい。
- ファイルのウィンドウも同期する。同じファイルを 2 つの Neovim で開くと、スワップファイルの警告が出て、変更がぶつかる。
- ターミナルだけのタブページを同期し、ファイルを含むタブページはその Neovim だけのものにする。ファイルを開いただけで、ほかの Neovim からタブページが消える。
- 引数なしの `nvim` だけで復元する。常に復元したい。
- ウィンドウを閉じたらプログラムも終了させる（herdr と同じ）。うっかり止める危険が大きい。
