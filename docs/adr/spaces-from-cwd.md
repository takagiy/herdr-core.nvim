# スペースは各ターミナルの今いるフォルダーの repo root で決め、Herdr アプリと label を共有する

## 状況

プロジェクトごとにエージェントやシェルをまとめたい。Neovim はほぼ `~` で起動し、タブを開いてから `cd` して `claude` を起動する、という使い方をしている。

Herdr のクライアント（デスクトップアプリ、スマートフォンアプリ）は、ターミナルの label で状態を共有している（[docs/labels.md](https://github.com/herdrdev/herdr-app/blob/5216e6f9f8c0c281a65e09816c66e4319e671784/docs/labels.md)）。`herdr.space` と `herdr.tab` を持つターミナルは、アプリのそのスペースとタブに表示される。

hc は、各ターミナルの前面のプロセスとそのフォルダーを 1 秒に 2 回ほど読み、変わると `foreground` イベントを出す。

## 決定

- 各ターミナルのスペースは、そのターミナルの今いるフォルダー（`foreground` の cwd）の git の repo root にする。git でなければ、そのフォルダーにする。
- `cd` するたびに決め直す。エージェントを起動したフォルダーも、このルールでそのままスペースになる。
- スペースはターミナル（ウィンドウ）ごとに決める。同じタブページに、別のスペースのターミナルが並んでもよい。
- スペースを作る・消す操作はない。その label を持つターミナルがある間だけ存在する。
- Herdr アプリと次の label を共有する。
  - `herdr.space`: スペース
  - `herdr.tab`: ターミナルごとに別の ID。アプリでは、ターミナル 1 つがタブ 1 つに見える
  - `herdr.seen`: どこまで見たか
  - `herdr.pinned`: ピン留め
- ほかのマシンのターミナル（`hc run --on`）は、できる範囲で対応する。実際のマシンを使った E2E の検証はしない。

## 結果

得たもの:

- いつもの流れ（`cd` → `claude`）のままで、エージェントがプロジェクトごとに分かれる。エージェントのプロセス名の一覧を持たなくてよい。
- スマートフォンアプリから、同じエージェントをプロジェクトごとに見て操作できる。「見た」とピン留めも、すべてのクライアントで同じになる。

失ったもの:

- シェルで `cd` するたびに、そのターミナルのスペースが変わる。
- Neovim のタブページと分割の形は、アプリには出ない。
- label の値にパス（`:` や `/` を含む）を使えるか、アプリがそれをスペースとして受け付けるかは、確かめていない。

## 採らなかった案

- スペースをターミナルの起動時に決めて固定する。`~` で開いてから `cd` するので、エージェントがすべて `~` に入る。
- エージェントの起動だけを検出して、スペースを決める。プロセス名の一覧が要る。`cd` に合わせるほうが、ルールが 1 つで済む。
- プラグインのコマンドでエージェントを起動し、そのときに label を付ける。シェルで `claude` と打つ使い方ができなくなる。
- シェル関数やエージェントの hooks で label を付ける。シェルやエージェントごとの設定が要る。
- スペースをタブページ単位にし、切り替えるとタブページを作り直す。herdr の見た目を再現するための仕組みで、複雑になる。
- Neovim 1 つを 1 プロジェクトにする。普段は `~` で 1 つの Neovim を使う。
- アプリの配置（doc `herdr-app`）も読み書きする。アプリの内部仕様に依存し、アプリの状態を壊すおそれがある。
