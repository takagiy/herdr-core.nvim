# 開いたターミナルは keep で起動し、エージェントの会話はフックが残した ID で再開する

## 状況

PC を再起動すると、hc のターミナルで動いていたプログラムはすべて終了し（`reason: host_shutdown`）、サイドバーが空になる。エージェントの会話も途切れる。

hc には `keep` がある。keep のターミナルは、プログラムを失うと、同じアドレスで最後の cwd のシェルに置き換わる。再起動のあとも、core が起動したときに戻る。元のコマンドは再実行しない。

Herdr デスクトップアプリは、自分で開くターミナルをすべて keep で起動する。会話の再開はしない。Herdr TUI は、エージェントのフックから会話 ID を受け取り、サーバーの再起動後に各エージェントの再開コマンドを実行する。hc には会話 ID を扱う機能がない。

## 決定

- プラグインが開くターミナルを keep で起動する。エージェントが `hc run` で起動した子は対象にしない。
- エージェントのフックが、会話を始めたときに、自分のターミナル（`HC_TERMINAL_ID`）に 2 つのラベルを 1 回の `hc label` で書く。会話を終えたときに 2 つとも空にする。
  - `herdr-core-nvim.agent`: integration の名前
  - `herdr-core-nvim.session`: 会話 ID
- Neovim を起動したときと `restarted` を受け取ったときに、ラベルが残っていて、前面のプログラムがその integration のエージェントではないターミナルを探す。エージェントかどうかは integration の `matches_program` が決める。見つけたら、2 つのラベルを空にしてから、integration の再開コマンドを `hc send` で打ち込む。ターミナルごとに 100 ミリ秒空ける。
- 前面のプログラムが変わったときには判断しない。エージェントを普通に終えると、終了のフックがラベルを消すより先に前面がシェルに変わる。
- プラグインがターミナルを開くときは、`CODEX_THREAD_ID`、`CLAUDECODE`、`CLAUDE_CODE_CHILD_SESSION` などを空にして渡す。
- 対象はこのマシンだけにする。hc の `restore_screen` には触れない。

## 結果

得たもの:

- 再起動しても、サイドバーとタブの並びがそのまま残り、エージェントは前の会話の続きから使える。
- 会話を自分で終えたターミナルは、シェルのまま戻る。強制終了された会話は、再起動のあとも、エージェントだけが落ちたあとも、次に Neovim を起動したときに戻る。
- プログラムの見分け方はデスクトップアプリと同じで、再開のほかにも使える。
- ラベルは打ち込む前に消すので、再開に失敗しても、起動のたびに打ち込み直すことはない。

失ったもの:

- フックを各エージェントの設定ファイルに入れる必要がある（[integration](integrations.md)）。
- Neovim を 2 つ同時に起動すると、同じ再開コマンドを 2 回打ち込むおそれがある。2 回目はエージェントへの入力になる。hc のラベルには、同時の書き換えの順序を決める仕組みがない。
- ほかのマシンのターミナルは、シェルまでしか戻らない。
- 前面のプログラムを見分け損なうと、動いているエージェントに再開コマンドを打ち込む。エージェントが自分の名前を報告せず、`node` などのインタープリターでスクリプト名の分からない形で動く場合に起こる。

## 採らなかった案

- keep だけにする（デスクトップアプリと同じ）。会話は自分で再開する。会話まで戻したい。
- 終了したターミナルを一覧に残し、最後の画面を読めるようにするだけにする。場所と並びも戻したい。
- 会話 ID を、エージェントの会話ファイルから cwd と時刻で推測する。同じフォルダーで複数のエージェントを並べて使うと、取り違える。
- ラベルを 1 つにまとめ、値を `<integration 名>:<会話 ID>` にする。分けたほうが読み書きしやすい。
- 前面がシェルかどうかで判断する。hc のエージェントの状態はエージェント自身の報告で、Windows ではシェルに戻っても消えない。シェルの一覧を持っても、シェルを `.cmd` で包む環境では見分けにくい。
- 会話を始めたときのルートのプログラムの pid をラベルに残し、keep で置き換わって pid が変わったときだけ再開する。動いているエージェントに打ち込むことはないが、エージェントだけが落ちた場合は戻らない。見分け方をデスクトップアプリとそろえれば、再開のほかにも使える。
- `restarted` イベントだけで再開する。再起動のあとは、プラグインが core を起動した直後にイベントが出るので、受け取る前に過ぎてしまう。
- 子のエージェントの環境変数を、core が取り除くのを待つ。core は最初に `hc` を呼んだプロセスの環境変数を受け継ぐ。エージェントが core を起動すると、その core の全ターミナルで codex のフックが「親がいる」と判断し、ラベルを書かなくなる。
- hc の `restore_screen` を設定する。会話を再開するエージェントでは画面が描き直される。ほかのクライアントにも効く hc の設定を書き換えることになり、デスクトップアプリも触れていない。
