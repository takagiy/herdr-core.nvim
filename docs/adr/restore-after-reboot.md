# 開いたターミナルは keep で起動し、エージェントの会話はフックが残した ID で再開する

## 状況

PC を再起動すると、hc のターミナルで動いていたプログラムはすべて終了し、サイドバーが空になる。エージェントの会話も途切れる。

hc の `keep` のターミナルは、プログラムを失うと、同じアドレスで最後の cwd のシェルに置き換わる。再起動のあとも、core が起動したときに戻る。元のコマンドは再実行しない。hc には会話 ID を扱う機能がない。

## 決定

- プラグインが開くターミナルを keep で起動する。
- エージェントのフックが、会話を始めたときに、自分のターミナルに integration の名前と会話 ID を label で書く。会話を終えたときに消す。
- Neovim を起動したときと hc の `restarted` を受け取ったときに、label が残っていて、前面のプログラムがそのエージェントではないターミナルを探す。見つけたら、label を消してから、再開コマンドを打ち込む。
- プラグインがターミナルを開くときは、エージェントが「親のエージェントの中にいる」と判断する環境変数（`CODEX_THREAD_ID`、`CLAUDECODE` など）を空にして渡す。

## 結果

得たもの:

- 再起動しても、サイドバーとタブの並びがそのまま残り、エージェントは前の会話の続きから使える。
- 会話を自分で終えたターミナルは、シェルのまま戻る。
- label は打ち込む前に消すので、再開に失敗しても、起動のたびに打ち込み直すことはない。

失ったもの:

- フックを各エージェントの設定ファイルに入れる必要がある（[integration](integrations.md)）。
- Neovim を 2 つ同時に起動すると、同じ再開コマンドを 2 回打ち込むおそれがある。hc の label には、同時の書き換えの順序を決める仕組みがない。
- 前面のプログラムを見分け損なうと、動いているエージェントに再開コマンドを打ち込む。

## 採らなかった案

- keep だけにする（デスクトップアプリと同じ）。会話まで戻したい。
- 会話 ID を、エージェントの会話ファイルから cwd と時刻で推測する。同じフォルダーで複数のエージェントを使うと、取り違える。
- 前面のプログラムが変わったときに判断する。エージェントを普通に終えると、終了のフックが label を消すより先に前面がシェルに変わる。
- 前面がシェルかどうかで判断する。hc のエージェントの状態はエージェント自身の報告で、Windows ではシェルに戻っても消えない。
- `restarted` イベントだけで再開する。再起動のあとは、プラグインが core を起動した直後にイベントが出るので、受け取る前に過ぎてしまう。
- 子のエージェントの環境変数を、core が取り除くのを待つ。core は最初に `hc` を呼んだプロセスの環境変数を受け継ぐ。エージェントが core を起動すると、その core の全ターミナルで codex のフックが「親がいる」と判断し、label を書かなくなる。
- hc の `restore_screen` を設定する。ほかのクライアントにも効く hc の設定を書き換えることになる。
