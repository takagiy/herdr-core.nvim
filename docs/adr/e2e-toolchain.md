# E2E は mini.test と実際の端末ジョブを使い、状態変化は Node.js の dummy agent から出す

## 状況

[実際の hc を通す E2E の決定](e2e-with-real-hc.md) を実装するため、Neovim の操作、状態変化、環境分離、CI での通知を動かす技術を決める。

## 決定

- E2E も mini.test の子の Neovim を使い、キーとマウスを実際の入力として送る。`hc attach` は製品と同じ terminal buffer で動かし、別の端末エミュレーターは使わない。
- dummy agent は Node.js の標準 API だけで書いた 1 本のスクリプトにする。attach を通した入力に応じて出力し、OSC 7501 で状態を報告する。Node.js は開発用の依存で、利用者には要求しない。
- 実行ごとに専用の hc のセッションと一時ディレクトリを作る。親のセッションを引き継がないよう、`HC_SOCKET`、`HC_TERMINAL_ID` などを取り除く。
- CI の通知は、仮想画面と D-Bus の中で実際の通知サービス（dunst）を動かし、既定の `notify-send` を実行する。

## 結果

得たもの:

- 通常テストと同じ言語・実行基盤で、実際の Neovim、hc、プログラムを通せる。
- 普段の hc の環境に触れずに実行できる。

失ったもの:

- E2E 用に Node.js と dummy agent の保守が要る。CI には通知用のパッケージも要る。
- 実際のエージェントの認証、応答、フックは検証しない。

## 採らなかった案

- 別のテストフレームワークや Python 製の画面操作基盤。mini.test と RPC で足りる。
- 上流の `fake_tui.py` を使う。`termios` と `tty` に依存し、Windows で使えない。
- Bash や Python で dummy agent を書く。入力に応じた状態変化を増やすときの書きやすさと OS 間の差から、Node.js にそろえる。
- 状態を変える RPC や偽のイベントを使う。実際のプロセスからの報告を通さない。
- 通知コマンドを、成功だけ返すスクリプトに差し替える。実際の通知機構まで通さない。
